# Chapter 11. What breaks

You and a friend are playing a strategy game in lockstep multiplayer against a computer opponent. Neither machine sends the other the state of the world. Each runs the full simulation itself, and only the players' orders travel over the network; as long as both machines start from the same state and apply the same orders on the same ticks, they stay identical. The opponent plans with Monte Carlo tree search, given a fixed slice of time to think before each decision.

Your friend's computer is faster. In the same slice of time it plays out more futures, and on one decision the move it has visited most is a different move from the one your machine settled on. For a few seconds nothing looks wrong. The two worlds have already split: on one screen the enemy's cavalry turns north, on the other it holds. Then the machines compare checksums, the numbers disagree, and the match stops with a desync error that neither of you can do anything about.

The dataset's record for the technique lists this exact failure: time-budgeted search returns different moves on different hardware, which breaks replays and lockstep multiplayer unless budgets are counted in iterations with seeded randomness. The fix is cheap once you know it. Count playouts instead of milliseconds, seed the random numbers, and every machine computes the same move. The record therefore marks the technique as mitigable.{{assert:field.monte-carlo-tree-search.determinism_impact == mitigable}}

AI techniques tend to fail inside simulation games in the same few places, because simulation games demand things that most software does not: the same inputs must produce the same world, every output a player sees becomes evidence for how the system works, and a single purchase has to pay for hundreds of hours of play.

## The same inputs, the same world

[[factorio|Factorio]]'s record notes that its item movement is discrete and deterministic, belts carrying a fixed number of items per second on two lanes, and that this is what lets its lockstep multiplayer simulate identical worlds on every machine. The same property supports a long list of things players never think about. A replay is a recording of inputs, played back through the same rules. A bug report from a player can be reproduced by loading the save and replaying the inputs. A leaderboard can be trusted because a submitted run can be re-simulated. A save file loads into the same world that was saved.

Each technique in the dataset records its effect on that property, and chapter 6 counted them. The ones that break it share a cause. A frame-generating world model, a language-model game master, a society of language agents, a realtime voice model: each samples its output, the sample depends on hardware and timing and the model's version, and its output decides what happens next.{{assert:field.genie-world-models.determinism_impact == breaks}}{{assert:field.llm-game-master.determinism_impact == breaks}}{{assert:field.llm-agent-societies.determinism_impact == breaks}}{{assert:field.realtime-voice-models.determinism_impact == breaks}}

A mitigable technique can be pinned down by seeding its randomness, storing its output, or bounding its computation by work instead of time. [[infinite-craft|Infinite Craft]] stores the output, as chapter 8 described.{{assert:field.llm-rule-adjudication.determinism_impact == mitigable}} A small model running on the player's own GPU can be seeded, which is why the record for on-device language models marks them mitigable too.{{assert:field.on-device-language-models.determinism_impact == mitigable}}

The techniques that leave reproducibility intact mostly never touch the simulation. Neural upscaling and frame generation work on the rendered image after the simulation has decided everything, which is part of why they became the one learned technique that is a norm in games (chapter 7).{{assert:field.neural-rendering-shaders.determinism_impact == preserves}}{{assert:field.neural-rendering-shaders.maturity == shipped-mainstream}} The others are deterministic algorithms run at play time, such as wave function collapse, which [[townscaper|Townscaper]] runs in real time to work out how the houses you place fit together.{{assert:field.wave-function-collapse.determinism_impact == preserves}} A deterministic algorithm can generate as much as it likes; given the same seed and the same clicks, it generates the same town.

The bets in chapter 10 inherit these properties from the techniques they apply. Of the {{stat:n_predictions}} opportunities, {{stat:n_opportunity_applies_breaking}} rely on at least one technique that breaks reproducibility outright.{{assert:n_opportunity_applies_breaking < n_predictions}} Each of them needs a plan for what the log records, or it gives up replays and multiplayer.

The requirement reaches mods too. The record for modding interfaces lists sandboxing and determinism requirements among a designer's levers, because in a lockstep game a mod runs on every machine and has to compute the same thing on each. A mod written from a sentence, the language-modding bet in chapter 10, inherits that requirement: the code has to be deterministic even though the model that wrote it is not. The record states the open problem directly, as a question about what interface design keeps generated mods sandboxed, deterministic, and compatible across updates.

## Where the computation happens

Each technique record also says where the technique runs: offline while content is made, as an assistant to a designer, on the player's machine during play, on a server during play, or over logged data after the fact. The place decides who pays and what can go wrong: {{stat:n_technique_server_realtime}} techniques can run on a server during play, and {{stat:n_technique_server_realtime_breaks}} of them break reproducibility outright; {{stat:n_technique_client_realtime}} can run on the player's machine, and {{stat:n_technique_client_realtime_breaks}} of those break it.{{assert:n_technique_server_realtime_breaks > n_technique_client_realtime_breaks}}{{assert:n_technique_client_realtime > n_technique_server_realtime}} Another {{stat:n_technique_offline_only}} never run during play; they are used while the game is made or on its telemetry, like the satellite reconstruction of chapter 7, whose output reaches the player as fixed data.{{assert:field.satellite-world-reconstruction.determinism_impact == preserves}}

{{viz:determinism-runtime}}

The techniques that run only on a server are where the breaks gather: of {{stat:n_technique_server_only}}, {{stat:n_technique_server_only_breaks}} break reproducibility, and every technique that breaks it can run on a server.{{assert:n_technique_server_only_breaks >= 5}}{{assert:n_technique_server_realtime_breaks == n_technique_runtime_breaks}}{{assert:n_technique_server_only_breaks > n_technique_client_realtime_breaks}} A server adds a network round trip to every call and a GPU bill per player, as the record for real-time restyling notes of its cloud stream. A hosted model may not be available to build on at all: the record for Google's world models describes access as a hosted research prototype for paying subscribers, with no public interface, hourly price, or version for the player's own machine published.{{assert:field.genie-world-models.maturity == prototype}}

## Contradiction

A contradiction does more damage than a gap, because players use what the game shows them to build their model of how it works. A colonist who mourns a friend who is alive, a road that was there a moment ago, a price that changes when nothing changed: each teaches the player something false.

Consistency is listed as a risk on {{stat:n_technique_risk_consistency}} of the {{count:technique}} techniques in the dataset,{{assert:n_technique_risk_consistency >= 15}} and chapter 8 gave the measured cases: a language model predicting text-game states, a world model letting a player jump in mid-air, language-model characters inventing quests. Characters forget, too. In a 28-player study with five language-model characters, players reported characters forgetting their own earlier statements in 10 percent of reports [@src-peng-2024-player-driven-emergence].

Generated pictures can contradict the state they stand for. Real-time restyling, whose door-shaped solid block chapter 7 described, can also change an object's appearance between views, because its record notes a short frame window and no long-term memory. In a frame-generating engine, health, ammunition, inventory, and score are only as reliable as the pixels that show them. Generated levels fail in their structure: an A* agent could not complete about 12 percent of the levels MarioGPT generated, so every output needs a solver to check it [@src-sudhakaran-2023-mariogpt], and EA's match-3 generator, conditioned on difficulty, matched the requested difficulty a third of the time [@src-villanueva-2024-match3-conditional-generation].

The pattern points to where a language model can safely sit. Asked to predict what the simulation will do, a model gets it wrong often enough to mislead. Asked to describe what the simulation did, from a log of events the simulation computed, it has the right answer in front of it. The record for language-model explanation of state draws the same line: explanations of dynamics should be computed by the simulation and only narrated by the model, and because the explanation layer reads state without writing it, the simulation stays deterministic.{{assert:field.llm-explanation-of-state.determinism_impact == preserves}}

## Opaque replacements

Deep simulations already struggle to be understood. Chapter 5 showed that the mechanics rated most emergent are rated hardest to read, and designers answered with a whole family of mechanics that own no simulation state and exist to explain the rest: overlays, inspectors, tooltips, chronicles. A learned component can undo that work. A policy trained to run a city's traffic or a rival's pricing may play well and still offer no reason for what it does, which moves the mechanic it replaced down the legibility scale.

Legibility is listed as a risk on {{stat:n_technique_risk_legibility}} techniques, including Monte Carlo tree search, whose choices come from thousands of playouts no player will see, and mean-field games, which replace a crowd of individual decisions with one representative agent responding to the population as a whole, so there is no individual decision to inspect.{{assert:n_technique_risk_legibility >= 5}} The remedy the dataset proposes is the same for every case: each learned component that affects state needs an explanation path, and the cheapest one is a log of what it decided and on what inputs.

## The bill

Most simulation games are sold once and played for a very long time. A feature that costs money every time a model is called turns each player-hour into a running cost. Compute cost is listed as a risk on {{stat:n_technique_risk_compute_cost}} techniques, second only to controllability.{{assert:n_technique_risk_compute_cost >= 20}}

The numbers behind that risk vary by orders of magnitude. The 25-agent Smallville simulation behind the original generative agents paper cost thousands of dollars in model credits and took several days of wall-clock time [@src-park-2023-generative-agents]; a later study cut token use for the same 25-agent town to 42.7 percent of the baseline by replaying cached plans [@src-yu-2024-affordable-generative-agents]. When Google opened Project Genie, built on its Genie 3 world model, to subscribers in January 2026, each generated world was limited to 60 seconds, a limit DeepMind attributed to limited compute [@src-techcrunch-2026-project-genie]. At the other end are the small on-device models of chapter 7, which fit beside the game's rendering on the player's own card. Local inference moves the cost onto the player's hardware and off the developer's bill, which is the case the local-first opportunity in chapter 10 makes.

## Latency

Latency is listed as a risk on {{stat:n_technique_risk_latency}} techniques.{{assert:n_technique_risk_latency >= 10}} The record for realtime voice, whose speech models chapter 7 timed, notes a trade: the most expressive delivery and the lowest latency pull against each other, and the most expressive speech synthesis was not suited to real time when it launched. Interactive video models are slower still: distillation took Hunyuan-GameCraft from 0.25 to 6.6 frames per second, with under five seconds of latency for each action [@src-li-2025-hunyuan-gamecraft], and the record notes that conditioning more strongly on history makes such a model more consistent and less responsive to new actions.

Small models on the player's machine trade the latency problem for a capability problem. The record for on-device language models notes that they reason less well over several steps, so vendors send strategic planning to cloud models, which brings back the cost and the latency the local model was meant to remove. It also notes that model sizes and latencies in shipped titles are mostly undisclosed.{{assert:field.on-device-language-models.determinism_impact == mitigable}}

## Steering and checking

The risk listed most often across all {{count:technique}} techniques is {{stat:top_technique_risk}}: the designer cannot reliably make the technique do what the design needs.{{assert:top_technique_risk == controllability}}{{assert:n_technique_risk_controllability > n_technique_risk_compute_cost}} It appears on {{stat:n_technique_risk_controllability}} of them. A language-model game master tends to accommodate requests a human game master would refuse [@src-gallotta-2024-llms-games-survey]. A world model accepts a prompt for weather or a new character mid-session and decides for itself what that looks like. A level generator produces something valid that no designer would have chosen.

Close behind is evaluation, listed on {{stat:n_technique_risk_evaluation}}: when a system can produce an unbounded variety of outputs, nobody can check them all.{{assert:n_technique_risk_evaluation >= 15}} Automated playtesting can check that generated content is valid and balanced; it says little about whether a generated event is any good. Human review does not scale to generated variety. This dataset faces the same problem with its own records and answers it with a verification queue: sampled, scored against anchors, and logged (chapter 13). Games will need something similar for what their generators produce.

Playtesting agents differ from players in skill and style, and agents that imitate players need large logs of real moves, which a new game lacks before launch. Rewards for coverage or curiosity stand in for the designer's intent, since, as chapter 7 noted, an open-ended sim gives them no single goal, and they can miss balance problems that appear only over long play. Societies of language agents are validated by matching stylized findings, which makes it hard for a designer to tune or test what the society does as a whole, and agents built on pretrained models reproduce institutions people already have, such as taxes, votes, and religion, so their outcomes are bounded by their training data.{{assert:field.automated-playtesting.maturity == shipped-niche}}{{assert:field.llm-agent-societies.maturity == research}}

## Trust, authorship, and safety

Players and the people who make games have their own reasons to distrust generated content, and chapter 7 covered how reception has gone: a moderation failure at AI Dungeon, a strike over voice replicas, and store rules that ask live generators to describe their guardrails.

These risks fall unevenly across the bets. Opportunities that help players understand a game or author more of it, such as explanation, modding by description, and orders given as intentions, replace no one's work and generate nothing a player did not ask for. Opportunities that replace authored writing, voices, or art carry the whole weight of the labor and trust questions.

## Provenance

Intellectual property and provenance are listed as a risk on {{stat:n_technique_risk_ip_provenance}} techniques, and several records trace it to training data.{{assert:n_technique_risk_ip_provenance >= 5}} The open interactive video models learned from recordings of commercial games: Hunyuan-GameCraft from more than a million recordings of over a hundred AAA titles [@src-li-2025-hunyuan-gamecraft], Matrix-Game 2.0 from about 1,200 hours that include Grand Theft Auto driving and Minecraft [@src-he-2025-matrix-game-2]. Their record calls the provenance of the output contested. The frame-predicting engines of chapter 7 are trained on footage of the game they reproduce, so their record describes the approach as cloning a game rather than authoring a new one and lists the licensing of that footage as unresolved. Learned level generators trained on commercial levels such as Super Mario Bros. raise the same questions for a shipped game, and text-to-3D models differ in where their training data came from and under what licence; TRELLIS is released under the MIT licence [@src-xiang-2024-trellis].

Some of the risk sits in data a studio would collect itself. The game-world model of chapter 7 shows the cost: its record says few studios hold years of consented play from one game. Models of human behaviour built from interviews need hours of data per person, which raises consent and privacy questions for player data. Even a technique that leaves reproducibility intact can carry the risk: rebuilding a planet from imagery needs a licensed imagery source.{{assert:field.satellite-world-reconstruction.maturity == shipped-niche}}

## Labor and safety

Labor displacement is listed on {{stat:n_technique_risk_labor}} techniques and content safety on {{stat:n_technique_risk_content_safety}}.{{assert:n_technique_risk_labor >= 5}}{{assert:n_technique_risk_content_safety >= 5}} The record for realtime voice carries both. Beyond the consent terms the strike won (chapter 7), the record notes that pay for replicas is now contracted, and that players have marked games down in reviews for AI voices. It also notes the control problem chapter 7 described: speech-native models are hard to hold to the actions a game allows.{{assert:field.realtime-voice-models.maturity == shipped-niche}}

A model on the player's machine needs its filters there too, and the record notes that players can extract or modify local weights. A shared cache has the opposite exposure: the record for language-model rule adjudication says that because every cached answer becomes permanent shared content, outputs must be filtered for offensive results. A hosted world model enforces its own limits; Genie's guardrails refuse copyrighted settings and nudity, which narrows the worlds players can make.

## Risks the bets name

The opportunity records list risks of their own, and many of them concern what a feature does to the game itself.

- A design that removes a chore can remove a skill. Intent-level orders risk hiding the systems some players enjoy mastering, and an ambiguous intent compiles to a surprising rule. Explained delegation risks a late game spent approving a manager's proposals, and a manager that imitates a novice repeats the novice's mistakes.
- A design that shapes events can feel rigged. The drama-aware storyteller lists players perceiving arc-shaped events as rigged, and the same arcs recurring across runs if the scoring is too deterministic. Placement that tells stories lists players arranging their towns for favourable events.
- A design that adds realism can take away play. Realistic weather can be less fun than authored seasons, research that depends on which scientists work together frustrates a player planning a build, and a workforce to manage can bury the logistics puzzle a factory player came for.
- The serious-sim bet lists users over-trusting calibrated outputs, and the planning sandbox lists simulated residents standing in for real community input, and political misuse.
- Balancing by search has blind spots. Bots find exploits humans never would and miss ones humans find, and balancing too hard removes asymmetries that make a game interesting.

## A log as the fix

One design answers several of these failures at once, and chapter 10 ranked it among the top bets. The event-sourced simulation runtime records every state change as an event with its inputs, its output, and its cause, including the changes a model decided. The log is the source of truth and the game state is a projection of it.{{assert:rank.opportunities-ranked.event-sourced-sim-runtime <= 5}}

Each failure above has a corresponding use of the log. A replay or a multiplayer client reads the logged output of a model call instead of calling the model again, so a technique that breaks reproducibility becomes reproducible after the fact; the opponent's move in the desynced match would have been decided once and sent to both machines as an event. A bug report includes the log, so the developer can step through what the model said. A why-query can cite the events that caused an outcome, and a branch preview can fork from any event. The record lists the precedents for the parts: [[dwarf-fortress|Dwarf Fortress]]'s legends, Factorio's deterministic lockstep, and [[eve-online|EVE Online]]'s persistent world.

The validation experiment is plain engineering. Wrap the model calls of an agent prototype in an event log, replay a hundred sessions, and check that the state is reconstructed byte for byte and that forked branches differ only after the fork point. Success is every replay reproducing, with the log adding less than 20 percent to the size of a save per hour of play. The prediction is that by the end of 2028 an engine, a middleware vendor, or an open-source project will ship an event-log replay layer designed for games with generative components, used by at least one title with 1,000 Steam reviews.{{assert:field.event-sourced-sim-runtime.falsifiable_signal.resolve_by == 2028-12-31}}

A second tool limits what a model can write in the first place. Constrained decoding masks every token that would take the output outside a schema or grammar, so a model asked for a game action can only produce an action the engine can execute, against targets that exist. A hosted structured-output mode reached 100 percent on a complex schema-following test, against under 40 percent for an earlier model without constraints [@src-openai-2024-structured-outputs]. Strict formats have a cost: they reduced models' reasoning accuracy compared with free-form answers, and stricter formats cost more [@src-tam-2024-let-me-speak-freely]. The record also states that no source documents constrained decoding in a specific shipped game; it is scored as research for games despite being routine elsewhere.{{assert:field.constrained-decoding.maturity == research}}

Together the two tools describe an architecture. The authoritative simulation stays symbolic and deterministic. Models propose changes in a typed format that a validator accepts or rejects, every accepted change is logged, and everything a player sees can be traced back to an entry in the log. The narrative engine behind Hidden Door applies the validator half of this design: it checks every story turn against its canon and rules before showing it [@src-hiddendoor-2026-homepage].

## Exercise: trace a failure

Pick an AI feature you have seen in a game, or one from chapter 10.

1. Write down what state it writes. If the answer is "none", say what it reads and what the player sees.
2. Decide whether a replay of the session would show the same output. If not, write what the log would have to record for it to do so.
3. Describe the first contradiction a player is likely to see, and how the player would find out that the game was wrong and not their understanding of it.
4. Estimate the cost per player-hour, and who pays it.

The exercise sorts features into two groups: those that can be fixed with a log and a schema, and those whose value depends on doing something no log can make repeatable.
