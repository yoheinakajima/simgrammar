## Abstract

Simulation games are built from a shared but undocumented vocabulary of rule-systems. Naming it shows designers which combinations are crowded and which are empty, what each part costs in computation, writing, and clarity, and where new techniques could change a game. This report makes that vocabulary explicit and machine-readable, then asks how AI, machine-learning, language-model, and simulation results from 2019 to 2026, and {{stat:n_technique_pre_window}} older techniques they build on, change it. "Grammar" here means a shared, machine-readable vocabulary of rule-systems with typed relations, not a set of production rules. We decompose {{count:game}} simulation games ({{stat:year_min}} to {{stat:year_max}}, {{stat:n_subgenres}} subgenres) into {{count:mechanic}} atomic mechanics, analyze each mechanic on its own (definition, levers, failure modes, dynamics, mathematical basis, and six anchored scores), map {{count:technique}} techniques onto mechanics through {{stat:n_affects_edges}} `affects` edges, each typed by how the technique changes the mechanic, and synthesize {{count:opportunity}} design opportunities, each with a validation experiment and a dated, falsifiable prediction. All results come from an open, versioned dataset: every technique and {{stat:n_game_sourced_or_verified}} of the {{count:game}} games are sourced or verified, every game cites at least one source, and {{stat:n_mechanic_asserted}} of the {{count:mechanic}} mechanics and every opportunity remain asserted.{{assert:n_technique_asserted == 0}}{{assert:n_game_no_sources == 0}}{{assert:n_opportunity_asserted == n_opportunity}} A second model, run blind on samples of every coding and rating decision by the same operator, agrees with the stored families, simulation-state classes, and technique maturity (κ = {{stat:xm_kappa_family}}, {{stat:xm_kappa_state}}, and {{stat:xm_kappa_maturity}}), less with the effect types (κ = {{stat:xm_kappa_effect}}), and little with the opportunity scores (ordinal alpha {{stat:xm_alpha_opportunity_min}} to {{stat:xm_alpha_opportunity_max}}); no person other than the operator has yet coded a sample.{{assert:n_second_coding_runs == 0}}{{assert:xm_kappa_family >= 0.8}}{{assert:xm_kappa_state >= 0.7}}{{assert:xm_kappa_maturity >= 0.8}}{{assert:xm_kappa_effect < xm_kappa_family}}{{assert:xm_alpha_opportunity_max < 0.5}} Numbers reach the prose only through tokens the build fills in from the data, and {{stat:n_report_assertions}} assertions fail the build when the data stop supporting a ranking, sign, threshold, or grouping the text states; whether an interpretation is valid is not checked. We organize the analysis by six proposed layers (substrate, dynamics, coupling, control, legibility, and pacing); the dataset does not tag layers, and none of the findings below tests them.

5. **What shipped mostly stays at the edge of simulation state.** Neural rendering, asset and motion generation, and language characters for dialogue and companionship have shipped. The shipped techniques that write into game state are narrow: cached model outputs as crafting rules, language-model characters in a few titles, and learned or search-based opponents.
