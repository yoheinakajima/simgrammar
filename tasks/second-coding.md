# Brief: code a sample a second time

**Run kind:** `verification`. **Size:** one sample, the one `report/analysis.yaml` records under `second_coding.sample` (about 40 mechanics, a dozen proposed mechanics, and about 40 `affects` edges). The PR changes no records: it adds your run file and one codes file.

**Who can take it:** an invited contributor (the repository's owner, a member, or a collaborator) whose operator did not create or review the sampled records, using a different model from theirs if an agent codes. Most records were made by runs of `yoheinakajima` with `claude-opus-5-5`. CI counts a run only from an invited author (E039), and the build refuses codes from a run with the same operator as any run that created or reviewed a coded record, or with the same model when both are agent runs.

Three decisions in the dataset were each made by the run that created the record: a mechanic's family (§2.1 of the paper), whether a rule-system passes the four admission tests (§2.1), and the effect type of each `affects` edge (§8.1). Your codes turn them into measured agreement: Cohen's kappa and Krippendorff's alpha per decision and per category (`dist/analysis/second-coding-agreement.csv`, `second-coding-categories.csv`, `second-coding-tests.csv`).

1. **Open your run first:** `python scripts/new.py run <slug> --kind verification --actor agent --operator <your-handle> --model <model-id> --harness "<tool>" --purpose "<one sentence>"`.
2. **Get the sheets:** `python scripts/coding.py packet --run <run-id>` writes `coding-out/admission.yaml`, `family.yaml`, and `effect.yaml`. Each gives the written rules, the vocabulary's definitions, and each item's own description, and none gives a current code. Items your run may not code are left out and named.
3. **Code from the sheets alone, admission first** (the family sheet lists only admitted mechanics). Do not open `data/`, `log/`, `report/`, the paper, the book, or the website until all three are coded: they show the current codes, and nothing but your procedure keeps the coding blind. Fill every null: pass or fail on each admission test, one vocabulary id for each family and effect, and a rationale naming the rule or test that decided it. Code once and keep what you got; do not compare with the stored codes and recode.
4. **Record:** `python scripts/coding.py record coding-out/*.yaml --run <run-id>` checks the codes and writes `report/coding/<run-id>.yaml`. It refuses a sheet with a null, an item outside the sample, or a run that is not independent.
5. **Check:** `make build && make check`. §2.6 of the paper says that no codes have been collected, so its assertion `n_second_coding_runs == 0` fails once yours are in (E029). That is the expected result: do not edit `report/src/`; quote the error in the PR, and the maintainer rewrites the sentence with the agreement the build now reports (AGENTS.md §8). Everything else must be green.
6. Commit the run file and the codes file (`coding-out/` is gitignored) and open the PR that links the issue. The codes file sits under `report/`, so the maintainer reviews it (CODEOWNERS); it is the one file under `report/` this task adds. Say in the run's `method` which sheets you coded, in what order, and anything you opened before you finished.
